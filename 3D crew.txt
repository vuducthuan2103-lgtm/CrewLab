# 3. Product Vision

CrewLab is a multi-agent marketing automation platform.

The Virtual Office turns the invisible AI system into a visible virtual marketing department.

Instead of only seeing:

```text
cards
statuses
content items
chat
approval screens
```

the customer enters a virtual 3D marketing office.

Every CrewLab agent becomes a virtual employee.

The customer becomes the:

> **CEO of their restaurant / cafe / business**

The CEO can:

* walk around the office;
* approach each employee;
* see agents working;
* see agents waiting;
* see agents reacting to workflow state;
* click an agent;
* inspect current work;
* see whether customer action is required;
* jump to the correct existing CrewLab screen.

The experience should communicate:

> "I have an AI marketing department working for my business."

# 4. Core Product Rule

## The 3D Office is a visualization layer.

It is NOT another workflow engine.

Existing CrewLab business ownership remains unchanged.

Examples:

### Allowed

```text
D02 needs customer image

3D Office
→ D02 shows waiting animation
→ customer clicks D02
→ panel says "Waiting for your image"
→ Open Asset Request
→ redirect to existing CrewLab screen
```

### Not Allowed

```text
3D Office
→ D02 has a completely separate upload workflow
```

---

Customer communicates with:

```text
A01
```

The customer does NOT directly command:

```text
B02
B03
D01
D02
E01
```

The office may display these agents and their work, but it must not create direct child-agent chat.

# 11. Visual State System

These are PRESENTATION states.

They are NOT new CrewLab backend workflow states.

Use approximately:

```ts
type AgentVisualState =
  | "idle"
  | "working"
  | "waiting_human"
  | "reviewing"
  | "reworking"
  | "success"
  | "error"
  | "rejected";
```

Expressions:

```ts
type AgentEmotion =
  | "neutral"
  | "focused"
  | "thinking"
  | "happy"
  | "concerned"
  | "urgent";
```

Never write these visual states back into CrewLab's domain workflow.

# 12. State Mapping

Backend state must be translated through one visualization adapter.

Architecture:

```text
CrewLab Backend State
        ↓
Office State Adapter
        ↓
Agent Visual State
        ↓
Animation + Expression
```

Example:

```text
E01 currently evaluating content
        ↓
E01 = reviewing
        ↓
review animation
focused expression
```

If backend data cannot prove that an agent is active:

```text
show idle
```

Do NOT invent agent activity.

Preferred order:

```text

        ↓
otherwise polling
```

```text

GLB size
repeated geometry
render loops
useFrame usage
```

Desktop target:

```text
approximately 50–60 FPS
```

Supported mobile target:

```text
approximately 30 FPS or higher
```

Functional correctness is more important than decorative effects.

---

# 37. Performance Rules

Do:

```text
lazy-load /office
compress assets
reuse geometry
limit shadow lights
pause unnecessary work
avoid frame-by-frame React state updates
```

Do NOT:

```text
set React state every frame
create hundreds of independent useFrame hooks
load all 3D assets globally
run heavy postprocessing by default
```
